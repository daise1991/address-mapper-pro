# 実装手順書：住所一括マッピングアプリ（Codex 単独）

住所リスト（CSV）を読み込み、緯度経度に変換して地図にピン表示するWebアプリを、
Codex に1タスクずつ頼んで作る手順。各タスクの「依頼文」をそのままコピーして使う。

- 構成：Vite + TypeScript（サーバーなし・ブラウザだけで動く）
- 地図：Leaflet + OpenStreetMap（無料・キー不要）
- 住所→緯度経度：国土地理院 住所検索API（無料）→ 失敗分のみ Google（任意）
- 結果はブラウザに保存し、同じ住所は二度と API に送らない

**進め方のルール**
- 1タスク終わるごとに動作・テストを確認し、git にコミットしてから次へ
- タスクごとに新しい会話にする（前の会話を引きずらない）
- 🧑 のタスクは人がやる（Codex に頼まない）

## T5. 国土地理院でジオコーディング
```
対象: src/geocode.ts（新規）とテスト
やること: geocodeGsi(address) を作る。
 エンドポイント: https://msearch.gsi.go.jp/address-search/AddressSearch?q=<住所>
 先頭の結果の座標を {lat, lng} で返し、結果なしは null。
 まず実際に1件リクエストしてレスポンス形式を確認してから実装すること（座標の並び順に注意）。
 さらに geocodeAll(addresses, onProgress) を作り、キャッシュにある住所は飛ばし、
 残りを1件ずつ・間隔500msで順番に処理して結果をキャッシュに保存する。
完了条件: fetch をモックしたテスト（成功・結果なし・キャッシュ済みで fetch が呼ばれない）が通ること
触らないもの: src/normalize.ts, src/csv.ts
```

## （任意）Google フォールバック
国土地理院で失敗が多い場合のみ。
1. 🧑 Google Cloud で Geocoding API を有効化し、キーを発行。
   キーには「HTTPリファラー制限」と「Geocoding API のみ」の制限を必ずかける。予算アラートも設定
2. 🧑 `.env` に `VITE_GOOGLE_API_KEY=...` を書く（git にコミットしない）
3. 依頼文：
```
対象: src/geocode.ts とテスト
やること: geocodeAll で国土地理院が null の住所だけ Google Geocoding API で再試行。
キーは import.meta.env.VITE_GOOGLE_API_KEY。未設定なら Google は使わない。
結果の source に "gsi" / "google" を記録。
完了条件: fetch をモックしたテスト（GSI成功時に Google を呼ばない／キー未設定時に呼ばない）が通ること
触らないもの: それ以外のファイル
```

## 困ったとき
| 症状 | 対処 |
|---|---|
| Codex が関係ないファイルまで変更した | `git checkout -- <ファイル>` で戻し、「触らないもの」を明記して再依頼 |
| 同じエラーで行き詰まる | 新しい会話で、エラーの該当数行と対象ファイル名だけ渡して再依頼 |
| 国土地理院APIがブラウザから呼べない（CORSエラー） | 「Vite の dev サーバーのプロキシ経由で呼ぶように変更」と依頼 |
| ピンが海の上に出る | 緯度と経度が逆。「T5 の座標の並び順を確認して修正」と依頼 |
