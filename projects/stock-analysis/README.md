# 日本株60銘柄 AI投資分析・自動検証 Webアプリ

2〜3年先（2028〜2029年度）の企業価値から割安株を買い、割高になった株を売るための分析アプリです。
**分析と通知までを自動化**し、**自動発注は行いません**。売買は利用者が内容を確認し、証券会社で発注します。

```
projects/stock-analysis/
├── backend/            Python 3.11+（FastAPI + SQLite）
│   ├── stock_analysis/
│   │   ├── providers/  J-Quants V2 / EDINET v2 / デモ（合成データ）
│   │   ├── scoring/    成長期待・買い（将来価値）・売り・判定ルール
│   │   ├── ingest.py   取得・重複排除・異常値/欠損検出・取得不可の記録
│   │   ├── pipeline.py 大引け後ジョブ（16:00〜18:00）
│   │   ├── verification.py  過去採点の検証・ルール精度比較
│   │   ├── portfolio.py     保有・余力・資金配分・翌営業日S株注文案
│   │   ├── notify.py        Web Push（iPhone/PC）
│   │   └── api.py           REST API ＋ フロント配信
│   └── tests/          pytest（53件）
├── frontend/           React + Vite + TypeScript（PWA）
└── docs/data-sources.md  データ提供元の調査結果
```

### 自動実行（タスク スケジューラ）

次のどちらかで設定します。

- **A: 常駐ループ**
  - ログオン時に `python -m stock_analysis scheduler` を起動します。
  - 15:55〜23:59 の間、15分おき（`STOCK_RETRY_INTERVAL_MIN`）に各段階を実行します。
- **B: 定時起動**
  - 平日 16:00 から 15分おきに、23:45 まで `python -m stock_analysis run-daily` を実行します。

どちらも同じ日に何度呼んでも安全です（冪等）。休場日は自動でスキップします。PCがスリープしていると動かないため、
**電源オプションで 15:30〜18:30 にスリープしない設定**にするか、常時稼働の小型PC・VPSで動かしてください。

### iPhone へのプッシュ通知

Web Push（VAPID）を使います。

1. `npx web-push generate-vapid-keys` で鍵を作り、`.env` に設定します。
2. HTTPS で公開します（Tailscale Funnel、Cloudflare Tunnel など）。**`STOCK_APP_TOKEN` は必ず設定してください。**
3. iPhone の Safari で開き、「共有 → ホーム画面に追加」を選びます（iOS 16.4 以降）。
4. 追加したアプリから「通知・システム → この端末で通知を受け取る」を押します。PC は Chrome/Edge でそのまま押せます。

## 大引け後の処理（JST・東証営業日のみ）

| 時刻 | 段階 | 内容 |
|---|---|---|
| 15:30 | — | 東証取引終了（2024/11/5 以降 15:30 クロージング・オークション） |
| 16:00 | fetch | 終値・出来高・決算・開示を取得します。月初に取引カレンダー、月曜に上場状況を同期します |
| 16:30 | score | 60銘柄の3種類の点数と判定を計算します |
| 17:00 | verify | 過去の採点の 20/60/120/250 営業日後リターンを計算します |
| 17:30 | finalize | ランキングと売買候補を確定します |
| 18:00 | publish | Webアプリを更新し、プッシュ通知を送ります |

- **営業日判定**: J-Quants 取引カレンダー（JPX公式データ）を使います。未取得の場合は土日・祝日・12/31〜1/3 で判定します。
- **終値が揃うまでの扱い**: 全監視銘柄の当日確定終値がそろうまで、score 以降は実行しません。古い株価で代用もしません。
  J-Quants の日足更新は 16:30 頃なので、16:00 の取得は通常「待機」になり、再試行で確定します。
- **締切（既定 20:00）を過ぎた場合**: 「データ遅延」を1回だけ通知します。その後も再取得を続け、データがそろった時点で残りの段階を実行します。

## 採点

### A. 成長期待点（100点）
次の7観点をそれぞれ0〜100点で評価し、重み付き平均で100点満点に合成します。

| 観点 | 重み | 評価に使うもの |
|---|---|---|
| 将来の売上成長 | 15 | 実績と会社予想 |
| 営業利益成長 | 15 | 実績と会社予想 |
| 市場規模の拡大 | 15 | 定性評価（根拠付きで手入力） |
| 競争優位性 | 15 | 定性評価（根拠付きで手入力） |
| 事業の収益性 | 15 | 営業利益率・ROE |
| 財務の安全性 | 10 | 自己資本比率・ネットキャッシュ・営業CF |
| 2028〜2029年の成長可能性 | 15 | 目標年度までのEPS年率と定性評価 |

- データがない観点は除外して再計算します。
- カバー率（重みの合計に対する、評価できた観点の割合）が50%未満の銘柄は**未算定**にします。

### B. 買い点数（将来価値方式）
```
将来株価 F = 予想EPS × 想定PER
現在理論価値 V = F ÷ (1 + 必要利回り)^年数        年数 = 目標決算期末までの年数（決算月を考慮）
買い点数 = max(0, min(100, 50 + 200 × (V/P − 1)))   小数点以下四捨五入（偶数丸めではない）
狙い目価格 = V × (1 − 安全余裕)
```
- **評価手法**: PER のほか、**正常化利益**（景気循環株）、**DCF**、**資産価値**（BPS×PBR）を選べます。
- **係数150との比較**: 係数150 で計算した値も毎回 `buy_score_k150` に保存し、検証画面で比較します。
- **必要利回り・安全余裕の初期値**: 安定 9%/10%、高成長 11%/15%、景気循環 13.5%/20%、新興赤字 15%/25%。
  銘柄ごとに変更でき、**理由の入力を必須**にして変更履歴を保存します。
- **未算定**: 赤字の EPS には PER を当てはめません。予測できない銘柄やETFは**未算定（NULL）**とし、0点とは区別します。
- **自動初期推計**: 前提を登録していない銘柄には、会社予想EPSに分類別の成長率と想定PERを当てた値を使い、画面に「自」と表示します。
  これは検証用の仮置きなので、**主要銘柄から順に根拠付きの前提へ置き換えてください**。

### C. 売り点数（100点）
- **観点と重み**:

  | 観点 | 重み |
  |---|---|
  | 割高度 | 25 |
  | 業績鈍化 | 15 |
  | 下方修正リスク（修正開示・進捗率） | 15 |
  | 財務悪化 | 15 |
  | 増資・希薄化 | 10 |
  | 株価過熱（RSI・移動平均乖離） | 10 |
  | 成長見通しの悪化 | 10 |
- **独立した評価**: 買い点数の逆数にはせず、観点ごとに個別に点数をつけます。
- **イベント要因の扱い**: 下方修正・増資の点数が80以上のときは、平均で薄めずに強く反映します。

### 判定
- **購入**:
  - 積極購入候補: 成長期待85以上・買い85以上・売り30以下
  - 通常購入候補: 成長期待80以上・買い75以上・売り40以下
  - 購入条件の確認対象: 買い65〜74
  - 割安待ち: 成長期待80以上だが買い65未満
- **売却**:
  - 売り85以上: 売却優先検討
  - 売り75〜84: 売却候補
  - 売り65〜74: 一部売却検討
  - 売り40〜64: 保有再評価
  - 売り39以下: 原則保有
- **利益確定と損切りの区別**: 売り65以上の銘柄を、売り要因の内訳で振り分けます。
  - **損切り・撤退**: 業績・財務系の要因が優勢、致命的な要因がある、または成長期待が60未満の場合
  - **利益確定**: 上記以外（割高・過熱が主因）の場合
- **閾値の変更**: `PUT /api/settings/rules` で変更できます。
- **取得単価・含み益**: 点数と判定には**使いません**。損益と税額（特定口座 20.315%）の試算にだけ使います。

## データ管理の原則

- **来歴の記録**: 全データに取得元・取得日時を保存します。決算データには対象決算期と公表日時も保存します。
- **先読み防止**: 採点にはその日までに公表済みのデータだけを使います。
- **取得失敗**: `fetch_log` に「取得不可」と記録します。過去のデータを最新扱いにはしません。
- **重複排除**: 主キーで上書きします。直近1週間は毎回取り直し、訂正を反映します。
- **品質チェック**: 次のケースを `data_quality_issues` に記録し、画面に表示します。
  - 前日比±30%超（分割調整なし）
  - 四本値（始値・高値・安値・終値）の不整合
  - 出来高0
  - 営業日の欠損
  - 分割・併合の検出
- **検証の区別**: 当日に保存した採点（live）と、後から再計算した採点（backfill）を区別します。
  backfill は「現在の評価前提」を使うため先読みバイアスを含みます。

## 銘柄の注意点（調査時点 2026-10）

- **464A QPSホールディングス**: 旧 5595 QPS研究所が株式移転したものです（2025/12/1 上場、1:1）。過去株価の連結が必要です（`CODE_PREDECESSORS`）。
- **2644**: ETF です。EPS ベースの買い点数は未算定とし、NAV 乖離での評価を今後追加します。
- **株式分割**: 2644（2024/10, 1:2）、6323（2024/9, 1:10）、1662（2024/10, 1:5）など。株価は J-Quants の調整後終値で分割の影響を除いています。
- **上場状況**: 起動後、J-Quants の上場銘柄一覧で毎週自動検証し、画面に「上場確認済／一覧に無し」を表示します。
